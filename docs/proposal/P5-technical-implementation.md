# Proposal page 5: Technical implementation and safety pipeline

_Draft by workstream A from the platform and the Master Plan. Items marked [B] or [C] describe the
domain engine and the AI pipeline and must be confirmed by those workstreams before submission._

## The idea in one line

**AI reads and explains; code decides.** No model output ever sets a dose, a time or a schedule.
Everything that touches a person's medicine or money is deterministic, tested code with a human
confirming the result.

## Architecture

| Layer             | What it is                                                                                         |
| ----------------- | -------------------------------------------------------------------------------------------------- |
| Phone app         | React Native (Expo) on Android, Bangla-first. Talks only to our API. Holds no secrets.             |
| API               | Node.js 22 and Fastify, TypeScript. Short-lived access tokens, rotating refresh tokens.            |
| Queue and workers | pg-boss on PostgreSQL 16: SMS sends, callbacks, reminders, reconciliation, nightly jobs. No Redis. |
| Data              | PostgreSQL 16. Phone numbers encrypted at the application level (AES-256-GCM).                     |
| Telecom           | Applink (OTP, SMS, Subscription, CaaS), called only from our server on a fixed IP.                 |
| AI                | OpenRouter models read prescriptions and reports and phrase explanations [C].                      |
| Schedule engine   | Pure TypeScript, deterministic, tested on 30 prescriptions [B].                                    |
| Hosting           | One always-free VM, Docker Compose, Caddy for HTTPS. CI builds and deploys every merge.            |

One TypeScript monorepo (`apps/api`, `apps/worker`, `apps/mobile`, `packages/*`) with shared,
validated contracts between the app and the server.

## The safety pipeline

1. **A photo is read by a model, never trusted.** The model returns structured fields with a
   confidence for each [C].
2. **Deterministic validators** check the brand against our drug table, parse the dose pattern with a
   fixed grammar, and sanity-check units and ranges [B][C].
3. **A human confirms.** The confirm screen shows the photo beside the fields, flags low-confidence
   values, and a pattern the parser cannot read is never guessed: the person types it [B].
4. **Only confirmed data becomes a schedule**, generated by the deterministic engine [B].
5. **Explanations are checked.** A numeric guard rejects any model sentence containing a number that
   is not in the confirmed data and falls back to a fixed template [C].
6. **Emergencies bypass the model.** A keyword guard for red-flag symptoms runs before any model call
   and shows the 999 banner [C].
7. **SMS replies and menus never call a model.** Reply codes are deterministic.

## Platform safety (what workstream A built)

- **Money:** the price is server-side config, never client input. The ledger is written before
  Applink is called. Money is exact integer poisha, never a float. Only Applink's charging
  notification settles a charge, and each charge grants its credit once.
- **Consent:** every subscription and every payment stores what was shown, the amount, the time and
  the device address, before anything is sent to Applink.
- **Privacy:** numbers stored encrypted; logs hold identifiers only and never numbers, codes, tokens,
  passwords or message text (proved by an automated audit of a full session); retention enforced
  nightly (message records 90 days, codes 1 day after expiry); an account can be deleted with a
  re-verified phone, keeping only an opt-out entry and an anonymous payment ledger.
- **Resilience:** callbacks are acknowledged first and processed from a durable queue; every handler
  is idempotent; failed jobs go to a dead-letter queue that is reviewed daily; unused payment codes
  are closed and stuck payments raise an alert.
- **Operations:** alerts on integration outages, a charge that needs a human, and dead letters;
  encrypted nightly backups to Cloudflare R2 with a tested restore; a written runbook.

## Delivery and cost

Every merge to `main` is linted, tested (including against a real PostgreSQL), secret-scanned,
built into container images and deployed by GitHub Actions. The whole production stack runs on
free tiers: one always-free VM with a fixed IPv4 (which Applink allow-lists), Cloudflare R2 for
backups and GitHub Actions for CI. [Mobile CI builds the APK: D.]

## Tests as evidence

Automated tests run on every push: the Applink client and the whole API against a local Applink that
validates every request body, and the queue, storage and billing layers against a real PostgreSQL.
The schedule engine has full branch coverage on 30 test prescriptions [B].
